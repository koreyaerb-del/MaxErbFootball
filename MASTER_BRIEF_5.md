## 4. The website & repository — technical internals (read before editing)

- **Live site:** https://maxerbfootballupdates.com  (page title: "Max Erb QB Tracker")

  Fonts: Barlow Condensed (display), IBM Plex Sans (body), IBM Plex Mono. Keep additions on these tokens.

### 4a. Encryption (this is why "guessing" happens — don't)
- The page content is **AES-GCM encrypted** and injected into `#app` after the visitor enters a password.
- On/around **line 373** there is one constant line:
  `var SALT = "…", IV = "…", CT = "…";`
- Scheme: **PBKDF2, 150,000 iterations, SHA-256** → **AES-GCM-256**; `SALT`, `IV`, `CT` are base64.
- The **decrypted plaintext IS the site's real content** (hero, stamps, results, game log, journal,
  and the gallery image JSON). You cannot read or trust the current status from the ciphertext — you
  must decrypt it with the password to see/edit it. **This is the source of truth, not web search.**

### 4b. What needs the password vs. what doesn't
- **Needs the page password (inside the encrypted blob):** record, next-up chip, depth chips,
  "Max's Role · Latest" banner, Season Results, QB Depth Chart, "Feedback from Max" journal,
  the 2026 Game Log table, the gallery images JSON (`#galdata`), and **BOTH timestamp stamps.**
- **Editable freely, no password (cleartext):** the sticky **"Watch Live" bar**, the gallery
  **slide list** (`var defs = [...]`), the `<title>`/meta, and top-level CSS.

### 4c. ⚠️ The TWO "updated" stamps — refresh BOTH, every single time
Both live inside the encrypted content, so updating them needs the password:
1. **Top strip** (~line 5): `<div class="mh-meta">Private &middot; Family &amp; Friends &middot; Updated <DATE · TIME TZ></div>`
2. **Footer** (~line 251): `<div>Last updated <DATE · TIME TZ> &middot; Weeks … </div>`
- **Format:** Mountain time, e.g. `Sep 27, 2026 &middot; 8:09 AM MDT`. **Always include the time-of-day.**
- (Optional fix Claude can install: a few lines of cleartext JS that auto-render "Last updated" from
  the file's build time, so the stamp is always right on deploy and never hand-edited. Ask Korey.)

### 4d. Gallery / photos
- Images map: `<script type="application/json" id="galdata">{ "key":"data:image/jpeg;base64,…", … }</script>`
  — **inside the encrypted blob.** Current keys: `heroA, heroB, coach, rival, team, w2keiser, w4pike`.
- Slide list: `var defs = [ {k:'key', c:'caption'}, … ]` — **cleartext** (~line 403), filtered by
  `IM[k]`. To add a photo: (1) add its data URL to `#galdata` (encrypted) AND (2) add a `{k,c}` entry
  to `defs` (cleartext). Convert large PNGs to JPEG (~q85) to keep the file lean.

### 4e. The "Watch Live" bar (reusable each game week)
- A sticky top bar linking to that week's stream(s), shown on both the gate and the unlocked page.
- Lives **just after `<body class="locked">`**, cleartext, between `WATCH LIVE BAR` / `END WATCH LIVE BAR`
  comment markers. Safe, quick, no-password weekly edit. **Remove it after the game.**

## 5. How to edit the encrypted content (cloud session, step-by-step)

1. **Get the page password from Korey in chat** (see Section 9 — never stored in the repo or this file).
2. **Decrypt** `CT` with PBKDF2(pw, SALT, 150000, SHA-256) → AES-GCM key; decrypt with `IV`. (Node
   `crypto.subtle` in the sandbox works.)
3. **Edit the decrypted plaintext** — make each change a verified exact string replace (assert exactly
   one match) so nothing silently misses.
4. **Update BOTH timestamps** (Section 4c) to the current date **and** time.
5. **Re-encrypt** with the **same SALT** but a **fresh random 12-byte IV** (never reuse an IV with the
   same key). Replace the `IV` and `CT` values on line 373; keep `SALT`.
6. **Verify:** re-decrypt the new file with the password and confirm every edit is present and it still
   unlocks.
7. **Hand `index.html` back** to Korey to upload; delete any scratch files that touched the password/plaintext.
